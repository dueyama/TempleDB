# Vercelでの試用デモ

`vercel_demo/`とrootの`vercel.json`は、Vercel上で架空データを試すための専用入口です。
ローカルの通常デモは従来どおり`bin/setup.sh`と`bin/run_demo.sh`を使います。

VercelではGitHub repositoryを取り込み、root directoryはrepositoryの先頭、frameworkはDjangoを選びます。
このデモ用コードを含むbranchを対象にします。専用の`DJANGO_SECRET_KEY`を暗号化環境変数へ設定します。
Python 3.13とDjango 5.2.19のruntime固定版を使い、buildで架空JSONからseedを新規生成します。
実DB・既存.env・backup・Google/OpenAIの認証情報を渡す必要はありません。

ログインは`demo` / `demo`です。ログイン画面に案内を表示し、初回表示では入力済みにします。
そのまま「ログイン」を押して試せます。ブラウザの署名cookieごとに一時copyを使い、変更履歴もそのcopyへ保存します。
新しい試用の最初のアクセス時に、日本時間のその日を基準として架空データを作ります。
法要予定・入金日・訪問日・年度設定の相対日付が、その開始日に合わせて生成されます。
試用中に日付が変わっても、開始日と編集内容を保ちます。ログアウト後は新しい開始日を使います。
故人の命日など、もともと固定された過去の日付はそのまま扱います。
元seedは変更しません。Vercelの実行環境が変わると編集内容が初期状態へ戻ることがあります。
ログアウトするとそのブラウザの識別Cookieを破棄し、次のアクセスはその日の初期データで始まります。
同じブラウザの別タブはデータを共有し、別ブラウザ/端末のデータとは分離されます。
Cookieはブラウザ終了時にも失効する設定ですが、ブラウザのセッション復元で戻る場合があります。
確実に初期化したい場合はログアウトしてください。他のブラウザは初期化されません。
ログアウトが完了すると、その実行環境にある当該ブラウザの一時コピーを削除します。
4時間アクセスのないコピーも、次のアクセス時に回収します。
同じ一時領域では16コピーまでとし、新規コピーで合計128MiBを超える場合も作成を待ちます。
利用中の別ブラウザを追い出さず、新しい利用者へ一時的な混雑案内を返します。
実際の個人情報・秘密を入力せず、日常業務のデータ保存には使わないでください。

この試用デモは、本運用のserver対応・永続保存・製品用のtenant分離の受入を意味しません。
架空デモは、Vercelの本番ドメインから誰でも`demo` / `demo`で試せる運用です。
preview等には別途Vercel認証がかかる場合があります。デモへのアクセスとソースrepositoryの公開範囲は別設定で、
GitHubをPrivateからPublicへ変更する必要はありません。
