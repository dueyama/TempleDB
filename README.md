# TempleDB

**寺院の日々の仕事に合わせて、AIと育てる寺務アプリ。**

TempleDBは、戸主・家族・過去帳、法要の予定、入金、名簿や帳票をまとめて扱う、日本語のWebアプリです。
実際の寺院業務で使いながら、改善を重ねてきました。

寺院によって、帳票の書き方、地区の扱い、法要の呼び方、配布の手順は少しずつ異なります。
TempleDBは、そうした違いを受け止める、**使うお寺に合わせて保守・拡張できるソースコードの雛形**です。

CodexなどのAIコーディング支援ツールと一緒に、仕組みを確認し、小さく変更し、
試してから日々の運用へ取り入れることを想定しています。

## できること

| 分野 | 主な機能 |
|---|---|
| 戸主・家族・過去帳 | 氏名、住所、連絡先、家族関係、法名、命日などの管理 |
| 法要・寺の予定 | 年回、中陰、葬儀、通夜、寺の行事などの予定・完了管理 |
| 入金 | お布施や護持会費などの記録 |
| 役員・配布先 | 地区役員、門徒総代、手配り・郵送の管理 |
| 印刷 | 年回案内、宛名ラベル、地区名簿、法要情報などの出力 |
| 変更履歴 | 対応する保存経路で、変更内容や操作者を記録 |
| 外部連携 | Googleカレンダーなどとの連携を必要に応じて設定 |

法要のルールや帳票の文面には、宗派・寺院ごとの確認と調整が必要です。

## まずは架空データで試す

実際の個人情報を用意せず、架空の戸主・家族・法要を使って操作を試せます。
基本のデモに、GoogleやOpenAIのAPIキーは必要ありません。

Codexなど、端末でファイル操作やコマンド実行ができるAIに、次の文章をそのまま渡してください。
リポジトリの取得からデモの起動まで、まとめて依頼できます。

> https://github.com/dueyama/TempleDB を、この端末の新しい作業フォルダに取得してください。
> 取得したSTART_HERE.mdとAGENTS.mdを読み、架空データのデモを動かしてください。
> この端末で何を準備するか、実行前に説明してください。

macOS / Linux / WSL2の基本操作は次のとおりです。Python 3.13以上を使用します。

```bash
./bin/setup.sh
./bin/run_demo.sh
```

setupはこのフォルダ内にPython仮想環境と依存ライブラリ、架空データのSQLiteを準備します。
Python自体の導入やOS全体の設定変更は、別途確認して進めます。

起動後、ブラウザで `http://127.0.0.1:8011/` を開きます。
デモの初期アカウントは `demo` / `demo` です。デモはこの端末からだけ接続する設定で使ってください。
終了は、起動したターミナルで `Ctrl+C` を押します。

Windows 11 ARM64には、PowerShellで動かす専用のデモ入口があります。
詳しい手順は[START_HERE.md](START_HERE.md)と[Windowsの説明](docs/windows_native_demo.md)を参照してください。

GitHubとVercelを連携して架空データの試用デモを置く場合は、[Vercelデモの説明](docs/vercel_demo.md)を参照してください。
Vercel版の編集内容はブラウザごとの一時保存で、ログアウトすると初期状態に戻ります。

## お寺に合わせて育てる

たとえば、AIに次のような追加・変更や日々の集計を相談できます。

- **お墓の管理**：
  「墓地の区画番号、使用者、連絡先、管理料を、家の情報と結び付けて管理したい」
- **納骨堂・永代供養の管理**：
  「申込み、納骨日、供養の内容、連絡先をまとめて記録したい」
- **月参り・お参りの予定**：
  「地区ごとに訪問予定をまとめ、持ち歩ける予定表を印刷したい」
- **法要・行事の準備**：
  「報恩講や彼岸会の出欠、役割分担、準備するものを一覧にしたい」
- **お寺独自の帳票**：
  「年回案内や地区名簿を、以前から使っている書式に合わせたい」
- **寺報に載せる一覧**：
  「昨年お亡くなりになった方の一覧を、地区・氏名・命日・享年など、お寺で使っている書式に合わせて出力したい」
- **昔の台帳からの移行**：
  「Excelや以前の寺院管理ソフトにある情報を、内容と関係を確認しながら移したい」

これらは、機能の追加や既存の検索・帳票を調整する相談例です。
AIと仕様を整理し、試験環境で動かして、確認できた変更から取り入れていきます。
詳しい依頼の進め方は[変更例](docs/sample_requests.md)を参照してください。

変更のために、[作業規則](AGENTS.md)、コードの役割分担、架空データの検証環境、保守試験を用意しています。
AIが作った変更も、差分と動作を確認し、Gitへ記録してから取り入れます。
既存の寺務データを使う場合は、バックアップと隔離した試験環境を先に準備します。

## 自分のお寺で使い始める

デモとは別の、空のデータベースから導入を準備できます。

既存の台帳や寺院管理ソフトから移す場合は、まず元データの項目と関係を調べ、変換方法を決めます。
取り込みを拡張するための基盤と、既存の取り込み実装を含んでいます。
移行先ごとに件数・関連・日付・履歴などを検証して進めます。

日々の運用へ移る前に、次を確認してください。

- 寺院情報、法要のルール、帳票の文面
- 利用者の権限と、使う端末・接続方法
- バックアップの保存先と復元方法
- 更新や不具合対応を担当する人

導入は[START_HERE.md](START_HERE.md)、運用の準備は[運用前の確認](docs/operations.md)、
データ移行は[AIと進める移行](docs/data_migration_with_ai.md)を入口にしてください。
GoogleカレンダーとAI/MCPは任意です。必要な場合だけ、自分の認証情報を非公開の保存先へ設定します。

## 技術と保守

Python / Djangoで作られています。継続運用の主系はPostgreSQL、デモとローカルの導入準備にはSQLiteを使用します。

```text
app/apps/office/     通常の寺務業務
app/apps/core/       共通設定・認証などの基盤
app/apps/imports/    取り込み、既存の業務モデル・migration
app/config/         設定・寺院ごとの方針
app/config/tenant_policy/default/  寺院ごとの文言・法要などの方針設定
datasets/           架空データ
maintenance/        隔離された保守試験
```

保守試験は次のコマンドで実行できます。

```bash
.venv/bin/python bin/test_maintenance.py
```

ソースと架空データの一時コピーを作り、新しいSQLiteでmigration・認証・主要業務を検証します。
Windows nativeで使うPythonとHTTP検査の手順も、[保守ガイド](docs/maintenance.md)に記載しています。

## 現在の公開範囲

初版は、**試用と導入準備のためのプレビュー版**です。

macOSでの新規セットアップ・隔離保守試験・HTTPログインを確認しています。
LinuxやWindows向けの入口も用意していますが、版ごとの確認状況は[環境と受入範囲](docs/platforms.md)に記載しています。
実際のプリンター、外部サービス連携、正式なサーバー運用などは、それぞれ利用環境での確認が必要です。

このリポジトリには、寺院の実データ、業務履歴、バックアップ、認証情報を含めません。
導入後に作る個人情報、実帳票、環境記録、ログ、秘密もGitへ追加せず、公開Issueへ載せないでください。
